# 채용/인재 기능 갭 분석 리포트

**분석일**: 2026-08-19
**비교 대상**: wone 현재 구현 vs 사람인/잡코리아/원티드

---

## 1. 현재 구현 현황

### DB 테이블
| 테이블 | 용도 | 비고 |
|---|---|---|
| `job_postings` | 채용공고 | company, title, region, employment_type, disability_friendly, salary, deadline, description |
| `job_applications` | 지원서 | job_id, user_id, name, email, phone, cover_letter. UNIQUE(job_id, user_id) |

- 인재 프로필은 DB 아님 — `core/constants.py`에 3건 하드코딩 (`TALENT_PROFILES`)

### 구현된 라우트
| 라우트 | 메서드 | 기능 |
|---|---|---|
| `/resume` | GET | 공고 목록 (q, region 필터) + 인재 탭 (하드코딩 3건) |
| `/resume/{id}` | GET | 공고 상세 + 지원 중복 체크 |
| `/talent/{id}` | GET | 인재 프로필 상세 (하드코딩) |
| `/job_apply/{id}` | GET | 지원서 작성 폼 (유저 정보 프리필) |
| `/api/job_apply/{id}` | POST | 지원서 제출 |
| `/erp_hr` | GET | HR 대시보드 (인원/휴가/공고 카운트) |
| `/recruitment_status` | GET | 채용현황 (공고 목록, 읽기전용) |

## 3. 우선순위 제안

### P0 - 납품 데모 필수 (없으면 ERP로서 기본이 안 됨)

| # | 기능 | 작업량 | 이유 |
|---|---|---|---|
| 1 | **공고 등록/수정/삭제 (관리자)** | 중 | 시드 데이터만으로는 데모 불가. 기존 ERP 문서 CRUD 패턴 재사용 가능 |
| 2 | **지원자 목록 열람 (관리자)** | 소 | job_applications 테이블 이미 있음. SELECT + 목록 템플릿만 추가 |
| 3 | **지원자 상태 관리** | 소~중 | job_applications에 status 컬럼 추가 (접수/서류합격/면접/합격/불합격). 상태 변경 API |
| 4 | **지원서 상세 열람** | 소 | 자기소개서 + 지원자 정보 표시 |

### P1 - 데모 품질 향상 (있으면 좋음)

| # | 기능 | 작업량 | 이유 |
|---|---|---|---|
| 5 | **인재 프로필 DB화** | 중 | 하드코딩 3건 → talent_profiles 테이블. 검색/필터 백엔드 연결 |
| 6 | **공고 상태 관리** | 소 | status 컬럼 (모집중/마감/임시저장) + 마감 처리 |
| 7 | **공고별 지원자 수 표시** | 소 | COUNT 쿼리 한 줄 |
| 8 | **합불 통보 (화면상 버튼)** | 소~중 | 실제 이메일 발송 없이 상태 변경 + "통보 완료" 표시만으로도 데모 가능 |

### P2 - 실서비스 수준 (납품 후 확장)

| # | 기능 | 작업량 |
|---|---|---|
| 9 | 면접 일정 관리 | 중 |
| 10 | 채용 단계 파이프라인 | 대 |
| 11 | 채용 제안(스카우트) 메시지 | 중 |
| 12 | 통계/퍼널 분석 | 중~대 |

### P3 - 과한 기능 (이 프로젝트 범위 밖)

- 칸반 보드, AI 스크리닝, 화상면접, 리마인더 자동 발송, 멀티플랫폼 게재, 공고 템플릿

### 보안 - 별도 처리 필요

| # | 항목 | 긴급도 |
|---|---|---|
| S1 | 개인정보 수집 동의 체크박스 (지원서 제출 시) | 높음 (법적) |
| S2 | 지원자 정보 보유기간 설정 + 자동 삭제 로직 | 중간 |

## 4. 요약

**현재**: 공고 보기 + 지원서 제출까지만 구현. 관리자가 지원자를 확인하거나 채용 프로세스를 진행하는 기능이 전무.

**최소 데모 수준(P0)**: 4개 기능 추가하면 "공고→지원→서류심사→합불" 흐름 완성. 기존 ERP 문서 CRUD 패턴 재사용으로 작업량 최소화 가능.

**보안**: 개인정보 동의 절차는 법적 요구사항이므로 데모라도 넣는 것을 권장.
